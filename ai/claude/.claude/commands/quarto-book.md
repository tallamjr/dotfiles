# Quarto Book Generator

Transform a folder containing markdown notes into a professionally structured Quarto book with proper configuration, chapter organisation, and format conversion.

## Arguments

- `$1` = Path to folder containing markdown notes (required)
- `$2` = Output directory for the Quarto book (optional, defaults to `<notes-folder>/book`)
- `$3` = Pass `--render` to automatically render the book after generation (optional)

## Instructions

### 1. Validate and Explore Source Folder

1. **Validate the source path** `$1`:
   - Confirm the folder exists
   - If not found, report error and exit

2. **Scan for markdown files**:
   - Use Glob to find all `*.md` files in the folder (including subdirectories)
   - Read each file to extract: title (first `# ` heading), content structure, any existing front matter
   - Build a chapter manifest with: filename, title, relative path, detected order (numeric prefix or alphabetical)

3. **Analyse content structure**:
   - Identify if files use GitHub admonitions (`> [!NOTE]`, `> [!TIP]`, etc.)
   - Check for figure references and their paths
   - Detect MathJax/LaTeX equations
   - Note any cross-references between files

### 2. Create Book Directory Structure

1. **Set up output directory**:
   - If `$2` provided, use that path; otherwise create `<notes-folder>/book`
   - Create the directory structure:
     ```
     <output-dir>/
       _quarto.yml
       index.qmd
       chapters/
       figures/          (if source has figures)
       styles.css        (optional custom styling)
     ```

2. **Copy or symlink figures**:
   - If source folder has a `figures/` directory, symlink it to `<output-dir>/figures`
   - Alternatively, copy figures if symlink not appropriate

### 3. Generate _quarto.yml Configuration

Create `<output-dir>/_quarto.yml` with the following structure:

```yaml
project:
  type: book
  output-dir: _book

book:
  title: "<Derived from folder name or first file>"
  subtitle: "<Optional - derive from content if possible>"
  author: "<Author name if found in source, otherwise omit>"
  date: "<Current year>"
  description: "<Brief description derived from index or first chapter>"

  sidebar:
    style: docked
    background: "#F5F5F5"
    search: true
    collapse-level: 1

  page-footer:
    left: "<Year>"
    right: "Built with [Quarto](https://quarto.org/)"

  chapters:
    - index.qmd
    # List all chapters in order
    - chapters/<chapter-1>.qmd
    - chapters/<chapter-2>.qmd
    # ... etc
    - references.qmd  # if bibliography exists

format:
  html:
    theme:
      light: cosmo
    css:
      - styles.css
    code-fold: false
    code-tools: true
    toc: true
    toc-depth: 3
    number-sections: true
    link-external-newwindow: true
    fig-cap-location: bottom
    html-math-method: mathjax
```

**Chapter ordering logic**:
- If files have numeric prefixes (01-, 02-, etc.), use that order
- If files have date prefixes (2024-01-15-), sort chronologically
- Otherwise, sort alphabetically
- Place README.md or index.md content in index.qmd

### 4. Convert Markdown Files to Quarto Format

For each markdown file, create a corresponding `.qmd` file in `<output-dir>/chapters/`:

#### 4.1 Add YAML Front Matter

```yaml
---
title: "<Extracted from first # heading>"
subtitle: "<Optional>"
---
```

#### 4.2 Convert GitHub Admonitions to Quarto Callouts

Transform:
```markdown
> [!NOTE]
> Content here
```

To:
```markdown
::: {.callout-note}
Content here
:::
```

Supported conversions:
- `[!NOTE]` -> `.callout-note`
- `[!TIP]` -> `.callout-tip`
- `[!IMPORTANT]` -> `.callout-important`
- `[!WARNING]` -> `.callout-warning`
- `[!CAUTION]` -> `.callout-caution`

#### 4.3 Update Figure Paths

- Update relative paths to point to the book's figure directory
- Convert `![alt](figures/image.png)` to `![alt](../figures/image.png)` or appropriate relative path

#### 4.4 Preserve Mathematical Content

- Keep `$...$` for inline math (MathJax compatible)
- Keep `$$...$$` for display math
- Quarto renders these correctly with `html-math-method: mathjax`

#### 4.5 Handle Code Blocks

- Preserve fenced code blocks with language hints
- Quarto supports syntax highlighting for common languages

### 5. Generate index.qmd

Create `<output-dir>/index.qmd` as the book's landing page:

```qmd
---
title: "<Book Title>"
subtitle: "<Subtitle if applicable>"
---

## Welcome

<Brief introduction derived from source content or generated summary>

## Contents

<Auto-generated list of chapters with descriptions>

### Part 1: <Section Name if applicable>
- **[Chapter 1: Title](chapters/chapter-01.qmd)** - Brief description
- **[Chapter 2: Title](chapters/chapter-02.qmd)** - Brief description

<etc.>

---

[Start reading ->](chapters/chapter-01.qmd)
```

### 6. Create Supporting Files

#### 6.1 styles.css (minimal custom styling)

```css
/* Custom styles for the book */
.callout {
  margin: 1em 0;
}

pre code {
  font-size: 0.9em;
}
```

#### 6.2 references.qmd (if bibliography exists)

```qmd
---
title: "References"
---

::: {#refs}
:::
```

### 7. Optional: Render the Book

If `--render` flag is passed as `$3`:

1. Run: `quarto render <output-dir>`
2. Report success/failure
3. Note the output location: `<output-dir>/_book/`

### 8. Verification

Use the Task tool to spawn a `verification-agent` subagent to verify:
- All source markdown files have corresponding .qmd files
- _quarto.yml is valid YAML with correct chapter references
- Figure paths are correct and files exist
- Callout conversions are properly formatted
- No broken internal links

### 9. Report Summary

Report:
- "Generated Quarto book in `<output-dir>`"
- Number of chapters converted
- Any warnings (missing figures, unconverted syntax)
- If rendered: location of HTML output
- Command to preview: `quarto preview <output-dir>`
- Command to render: `quarto render <output-dir>`

## Output Structure

```
<output-dir>/
  _quarto.yml              # Book configuration
  index.qmd                # Landing page
  styles.css               # Custom styling
  references.qmd           # Bibliography (if applicable)
  chapters/
    chapter-01.qmd
    chapter-02.qmd
    ...
  figures/                 # Symlinked or copied from source
    image-01.png
    ...
  _book/                   # Rendered output (if --render used)

    ...
```

## Example Usage

```bash
# Basic: generate book structure from notes folder
/quarto-book ~/notes/ml-course

# Specify output directory
/quarto-book ~/notes/ml-course ~/books/ml-course-book

# Generate and render immediately
/quarto-book ~/notes/ml-course ~/books/ml-course-book --render

# Use current directory notes
/quarto-book ./lecture-notes
```

## Conversion Reference

### GitHub Admonition to Quarto Callout

| GitHub Syntax | Quarto Syntax |
|---------------|---------------|
| `> [!NOTE]` | `::: {.callout-note}` |
| `> [!TIP]` | `::: {.callout-tip}` |
| `> [!IMPORTANT]` | `::: {.callout-important}` |
| `> [!WARNING]` | `::: {.callout-warning}` |
| `> [!CAUTION]` | `::: {.callout-caution}` |

### Cross-Reference Syntax

For adding cross-references in Quarto:
- Figures: `![Caption](image.png){#fig-label}` then `@fig-label`
- Equations: `$$ equation $$ {#eq-label}` then `@eq-label`
- Sections: `## Section {#sec-label}` then `@sec-label`
- Tables: Use div syntax with `{#tbl-label}`

## Advanced Features

### Parts and Sections

For larger books, organise chapters into parts:

```yaml
chapters:
  - index.qmd
  - part: "Part 1: Fundamentals"
    chapters:
      - chapters/intro.qmd
      - chapters/basics.qmd
  - part: "Part 2: Advanced Topics"
    chapters:
      - chapters/advanced-01.qmd
      - chapters/advanced-02.qmd
```

### Appendices

Add appendices after main chapters:

```yaml
chapters:
  - index.qmd
  - chapters/chapter-01.qmd
appendices:
  - appendix-a.qmd
  - appendix-b.qmd
```

### Multiple Output Formats

Extend format section for PDF/EPUB:

```yaml
format:
  html:
    theme: cosmo
  pdf:
    documentclass: scrreprt
  epub:
    cover-image: cover.png
```

## Notes

- Quarto must be installed: https://quarto.org/docs/get-started/
- For PDF output, a LaTeX distribution is required
- Preview with live reload: `quarto preview <output-dir>`
- The conversion preserves original markdown files; they are not modified
